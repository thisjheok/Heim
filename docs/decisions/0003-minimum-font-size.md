# 0003. UI 글자 크기 하한: 정보가 많으면 폰트를 줄이지 않고 구조를 바꾼다
- 날짜: 2026-10-27
- 상태: 채택

## 맥락
초안 검토 카드에서 질문·가정·사양을 `<small>`과 8~11px 글자로 한 줄에 몰아넣어 읽기 어려웠다.
앱 전반에도 8~10px 글자가 많았고, 넓은 화면용 override로 일부만 키우고 있었다.

## 결정
- 글자 크기는 `app/src/index.css`의 `:root` 토큰으로만 쓴다.
  - `--text-caption` 12px: 배지, 메타 정보, 시간, 라벨 등 보조 텍스트. **하한.**
  - `--text-body` 13px: 본문, 목록, 버튼, 입력, 행.
  - `--text-title` 14px: 카드·섹션 제목. 그보다 큰 헤딩은 px로 직접 쓴다.
- 12px 미만은 어떤 화면 폭에서도 쓰지 않는다. 좁은 화면 media query에서도 폰트를 줄이지 않는다.
- 정보가 많으면 다음 순서로 해결한다:
  1. 가로 나열 대신 세로 목록(`<ul>`)으로 쌓는다.
  2. 부가 정보(근거, 가정 등)는 `<details>`로 접고 개수를 보여준다.
  3. 그래도 많으면 탭이나 상세 패널로 옮긴다.
- 범용 자식 선택자(`.x > div:last-child` 등)가 새 요소의 배치를 바꾸지 않는지 확인한다.

## 기각한 대안
- 화면 폭별로 폰트를 줄여 맞추기 — 이번 문제의 원인이다.

## 결과
- 기존 12px 미만 값은 모두 토큰으로 올렸다. 노드 카드처럼 폭이 고정된 곳은 말줄임표(ellipsis)로 처리된다.
